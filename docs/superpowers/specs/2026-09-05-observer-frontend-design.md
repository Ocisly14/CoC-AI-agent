# 观察者前端 — 设计

> 状态：已补齐历史、鉴权、时钟与实时订阅契约；视觉方向按用户最新决定改为 HD-2D 与“全局地图 → 局部场景 → 内部空间”的分级浏览，待实现。
> 范围：**只做观察者模式**。玩家模式不在本次范围内，但阅读栏的组件边界按"以后底部能挂一个动作框"来划。

> 上述线框图与风格板属于旧版手绘方案，仅供布局沿革参考；画面、导航与文案以本文为准。

## 1. 背景与目标

后端是一个按分钟推进的 LLM 世界模拟：每个角色是一个自己感知、自己决定、自己写记忆的 agent；世界由代码引擎和 LLM 引擎共同推进。现有前端（`client/src/views/SimulationPage.tsx` 加 Phaser 镇景）是在旧架构上长出来的。本次重做画面与观察方式，让分级地图负责探索地点，让阅读栏呈现后端最丰富的感知、决定和记忆。

本设计从头定义观察者看到的界面。它的第一用户是**观察者兼实验员**：上帝视角看小镇里涌现的故事，随时切到某个人的眼睛看他所见所为，并能拨天气、投事件、注入角色。

**本版只服务作者自己的项目，不要求通用模组适配。** 场景、美术、地图布局和命名可以针对项目手工制作，不设计通用素材库、模组皮肤或零配置生成系统。视觉参考《八方旅人》的 HD-2D：像素角色与贴图、立体场景、光影与景深。沙盘首先是一张可以缩放的全局地图；放大到地点时逐步展示场景细节，点击场景后进入内部空间。

**核心是文字，画面用于定位、导航与营造氛围。** 视觉目标是在不实时建模、不逐拍生成美术的前提下尽量实现 HD-2D 的观感。感知、决定、记忆和场景描述承担完整表达；画面只映射其中能可靠且低成本表现的部分。美术覆盖率、场景加载和动画制作不能成为阅读功能或世界模拟的前置条件。

与小镇时间的关系是**按真实分钟节奏运行，以已结算的游戏时间为准**。`SimulationRunner.enableRealTimeSync` 只在启用时对齐时分并保留游戏日期，之后每拍推进一个游戏分钟；暂停或慢拍会让它落后于墙上时钟。本版沿用这一推进方式，不跳过游戏分钟，也不新增加速追赶。观察者随时进来看最新已结算的世界，离开再回来先读"这期间发生了什么"。具体时钟与暂停规则见第 7 节。

## 2. 数据约束与项目范围

画面可以精心制作，模拟信息仍以现有后端为准：

1. **后端提供地点关系与文本，前端提供视觉布景。** 地图布局、建筑外观、室内家具和角色精灵可以手工制作。后端确定角色所在场景与道路进度；前端将这些状态映射到对应画面，不把布景中的厘米级位置或装饰物当成新增模拟事实。
2. **世界已经是超文本。** 每段描述以 `[id]` 内嵌引用物品、地点、人物；角色能指向的只有段落里出现过的标签。前端把引用渲染成链接，导航结构不需要另行发明。
3. **信息不对称是核心玩法。** 同一分钟每个人读到的段落不同（清晰度 full / limited / trace）。前端呈现"某个人的视角"时必须忠实：只给他读到的，不补上帝视角。
4. **一分钟一拍，大多数拍是空的。** 一小时六十拍里只有几拍值得看。时间轴必须显示密度，没变化的分钟必须折叠。
5. **只有一个时钟。** 顶栏显示服务端已结算的游戏时间，不用浏览器墙上时钟推进；回看时显示所选历史时间。运行节奏与结算状态单独用状态文字表达。
6. **前端路径上不新增任何模型调用。** 摘要、密度、折叠、显著度全部由代码从落库记录推导。视觉标签可随已有结算输出附带，不增加模型调用轮次；前端只按固定标签查表，不再解释自然语言。
7. **视觉投入服从文字体验。** 允许为本项目预先制作或离线生成贴图、精灵、简单模型和场景布局；运行时复用这些资源，不根据每拍叙述生成模型、贴图或完整场景。不承担通用模组支持和皮肤系统，也不为画面引入角色必须遵循的有限动作列表。

## 3. 主屏：大厅态

一屏四个区域，固定布局：

```
┌─ 顶栏：灰港镇 │ 1985-07-08 一 14:32 │ 雾 2/10 │ 14 人在镇 │ 2 人在路上 │ 运行中 │ 操作台 ▸ ────────┐
├─ 左栏 220px ────┬─ 沙盘（其余宽度）──────────────────────────────────────────────────┤
│ 自上次以来        │  全局：地形、道路、地点轮廓与活动标记，不展示建筑细节                       │
│ 你离开了 3h12m   │  放大：目标区域逐步显现场景，出现建筑、像素人物与局部光影                   │
│ · 11:20 Priya …  │  点击场景：进入其内部空间；面包屑可返回局部或全局                          │
│ · 12:05 Marisol …│  最近 10 分钟有事的地点显示活动标记；昼夜与天气影响场景氛围                  │
│ · 12:41 Earl …   │  点击人物：右侧展开阅读栏，查看其感知、决定与记忆                           │
├─ 时间带 ─────────┴───────────────────────────────────────────────────────────────────┤
│ 06:00 ······|··||·····|·······||···|···· ▮ ·········· 现在 14:32                           │
│ 竖线高度 = 那一分钟牵涉的人数；拖手柄回到任一分钟，沙盘和左栏同步回到那一刻；松手回"现在"     │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

- **顶栏**：模组名；一个时钟；天气芯片（区域天气，按 `weatherPresets` 的区域）；在镇 / 在路上人数；模拟状态（运行、暂停、结算中，见第 7 节）；操作台按钮。
- **沙盘**：Three.js / React Three Fiber 绘制，采用全局、局部、内部空间三级视图（第 3.1 节）。缩放决定外部地图的细节层级，点击场景决定是否进入内部。全局聚合人物与活动信息，局部和室内显示像素人物。地图与室内布景使用本项目专用的视觉配置，直接绑定已有地点、道路、场景、角色和物品 id。
- **左栏**：摘要流（第 5.3 节）。默认显示"自上次以来"；按用户和会话保存上次查看的已结算游标及离开时刻，首次打开显示游戏时间的"今天"。"你离开了多久"是现实经过时长，摘要范围按游戏记录计算，暂停期间不虚构事件。点一条：时间带跳到那一分钟，沙盘聚焦到那条的当事人。
- **时间带**：分钟分辨率，显示当天。密度来自第 5.3 节。拖动时进入**回看态**：沙盘用那一分钟的快照重绘，左栏摘要范围改为"到那一分钟为止"，聚焦态的流滚到那一分钟。松手回"现在"。回看态是只读的，操作台在回看态禁用。
- **操作台**：从顶栏拉出的抽屉，复用现有的暂停 / 继续 / 单步、天气、脚本事件、注入角色接口。不在本设计里重画。

### 3.1 三级浏览：全局地图 → 局部场景 → 内部空间

| 层级 | 展示内容 | 进入与退出 |
|---|---|---|
| **全局地图** | 地形、道路、地点名称和简化轮廓；地点人数、道路上的聚合标记和最近活动。不加载/绘制窗户、家具等建筑细节，不铺满人物姓名 | 初始视图；拖动平移，滚轮/触控缩放。点地点标记可把镜头定位并放大到该区域 |
| **局部场景** | 放大区域内的街道、建筑外观、植被、场景入口和像素人物；显示局部天气、灯光与阴影 | 放大达到阈值时逐步替换简化表现；缩小时退回全局。点击具体场景入口进入内部空间 |
| **内部空间** | 选中场景的房间、家具、物品与在场人物；使用剖面/隐藏屋顶的 HD-2D 布景，优先保证室内可读性 | 明确点击场景后进入，不能仅因继续滚轮放大而误入。面包屑“全局地图 / 地点 / 房间”及返回按钮恢复上一级镜头；多个房间按实际 scene id 切换 |

全局到局部是在同一地图上的连续缩放，地点坐标和选中对象保持稳定；地图轮廓在接近时淡出，对应的详细布景淡入。内部空间是独立的场景浏览状态：默认用短暂淡变和镜头过渡切入独立布景，不要求把全部室内都真实塞进全局建筑。返回局部时恢复进入前的中心、缩放和朝向。

**细节层级与导航分开管理**：全局/局部的 LOD 由地点在屏幕上的投影尺寸决定，按区域更新，不因为放大一个地点就展示整个地图的详细建筑。进入、退出局部细节使用不同阈值，避免在边界反复闪烁。地图采用固定倾角的正交相机并限制自由旋转；缩放、窗口尺寸及阅读栏开合都会改变屏幕覆盖率，均须重算层级。不能只依赖模型到相机的距离判断细节。

**按需加载**：首屏只载全局资源；接近阈值时预加载可见区域及少量邻近场景；进入内部前才加载对应室内资源。细节未就绪时保留简化地图并显示加载状态，不能先隐藏旧画面造成空白。缓存最近访问的场景并设置内存上限，共享贴图按引用计数管理，离开区域后停止不可见场景动画并按缓存策略释放 GPU 资源。切换期间的异步结果按导航版本校验，迟到的加载不能把用户拉回已离开的房间。

### 3.2 视觉风格：HD-2D

以《八方旅人》的像素美术与立体光影结合为视觉参考，制作本项目自己的地点与角色。全局地图保持清晰、简化；局部和内部空间承担主要的氛围与细节。

- **场景**：立体地形与建筑体块配合像素贴图；树木、装饰可结合精灵平面。重点地点允许单独制作外观和室内布景，按项目需要投入美术，不要求程序自动生成。
- **角色**：使用朝向镜头的像素精灵，统一像素密度、人物比例和地面锚点。全局聚合显示，局部/室内按场景成员展开；室内人物在建筑入口显示人数，进入对应房间后才出现精灵，不把他们画到室外街道。悬停或选中才显示姓名与状态，避免名牌遮挡画面。
- **光影**：局部采用冷暖环境光、窗灯、接地阴影与克制的泛光；昼夜和天气参数读取当前选中的已结算快照。全局弱化后处理，局部/室内可使用浅景深，但选中人物和可点击入口必须清晰。
- **像素质感**：精灵与贴图控制采样方式和显示尺度，避免糊成低分辨率照片；不对整个网页套像素化滤镜。镜头、材质和后处理一起调试，重点验证慢速缩放时贴图闪烁、精灵边缘和透明物体遮挡。
- **界面**：阅读栏、时间带、操作台保持 React DOM，采用与场景协调的深色半透明面板、细边框和清晰中文正文。文字链接、选择、复制和滚动独立于画布，不随场景景深模糊。
- **表现边界**：角色位置与道路进度按快照映射到视觉路径和预设站位；装饰性家具可以丰富画面，只有绑定后端实体 id 的物品才提供实体交互。`spot` 原文作为人物状态显示，不从自由文本猜出精确姿势或动作动画。待机动画只是视觉循环，不推动模拟。

室内结构和装饰是项目制作的静态布景，本次不还原历史装修、物品摆放或损坏外观。回看恢复已记录的人物、状态、天气与封路；地点文字和无历史数据的布景标为当前资料，不能暗示它们完整还原了当时场景。

#### 3.2.1 变化表现：预制布景与轻量状态层

一处地点由预制布景、可独立显示的角色/物品、灯光与少量特效组成。运行时只做资源加载、位置插值、精灵帧切换、显示/隐藏、颜色/灯光调整和预制变体切换。LOD 切换复用预制层级，不能触发根据文本重新建模。基础建筑、地面和装饰可以合并制作；需要拿走、销毁或显隐的实体物品必须是独立层，不能烘焙进背景图后再期待它动态消失。

| 变化 | 第一版表现 | 未覆盖的部分 |
|---|---|---|
| 角色移动与行动 | 按已结算位置移动精灵，使用少量待机/行走帧；选中时显示“正在……”与进度 | 揉面、检查伤口、争论等开放动作由文字表达，不逐个制作动画，也不按动作文字猜姿态 |
| 角色状态与外貌 | 更新状态量表；有明确数据和现成素材映射时切换预制覆盖层 | 未制作的衣着、伤痕或复杂外貌变化显示最新文字，不临时生成角色图或模型 |
| 物品出现、转移、消失 | 在有可靠实体绑定和状态数据时显示/隐藏独立精灵；随身变化更新清单 | 新物品没有素材时使用统一的物品标记加名称；复杂形态变化以描述更新为准 |
| 灯光、天气与通路 | 调整光源、颜色、雾层和通路标记；燃烧等效果由第 3.2.2 节视觉标签触发预制表现 | 没有标签/素材映射的坍塌或破坏细节只提示变化并展示描述，不建立实时破坏系统 |
| 只有描述发生变化 | 给实体或地点一个短暂、低干扰的“描述已更新”提示，点击读最新文字 | 画面保持示意，标明外观未完整反映文字；不强行把任意自然语言转换成视觉标签 |

变化提示只是导航提示，不替代角色实际感知；客观实体资料与角色阅读流仍保持边界。持续状态从所选数据恢复，短暂提示按事件 id 去重，只对正在观看时的新变化播放；首次加载、断线补帧和回看直接显示目标状态，不连播积压动画。动画不阻塞下一拍数据或阅读栏更新。

第一版优先绑定已记录的角色位置/状态、天气和封路。物品显隐、转移和灯具变化可作为后续小步增强，前提是已有可靠状态来源；若要求它们随时间回看，先补相应历史字段，不能把最新物品状态塞入旧快照。本轮不因此扩大为完整场景历史重建，也不为了判断画面应如何变化新增模型调用或改造引擎的自由文本动作体系。

#### 3.2.2 视觉标签：emoji 词汇驱动预制效果

**流程：文字与已确认结算 → 附带视觉标签 → 前端查表 → emoji / 预制效果。** 模型在已有结算输出中顺带标注少量可见表现，前端不再从段落里识别“是否着火”“是否愤怒”，也不请求额外模型判断。标签是可选的视觉注释，不是新的行动类别、世界规则或角色心理状态；没有标签时文字仍然完整。

程序协议使用稳定的 `effect` 名称，项目效果表负责映射 emoji、允许的对象类型、持续方式和预制表现。emoji 便于人理解，也可直接作为尚未制作特效时的画面回退；模型不同时输出 emoji、粒子参数和模型路径。首版只支持下列六种，后续按需要扩展：

| effect | emoji | 适用对象 | 生命周期 | 局部 / 室内的表现 |
|---|---|---|---|---|
| `burning` | 🔥 | 角色、物品、场景 | 持续，start / stop | 预制火焰精灵与暖色光；没有素材时显示火焰图标 |
| `speaking` | 💬 | 角色 | 瞬间，pulse | 短暂说话气泡，原话仍在阅读栏；可由已确认的 speech occurrence 直接生成 |
| `angry_expression` | 😠 | 角色 | 瞬间，pulse | 头顶短暂表情或轻微强调动画，只表达可观察的愤怒表现 |
| `sleeping` | 💤 | 角色 | 持续，start / stop | 睡眠符号与已有待机变体，不反向修改角色行动状态 |
| `impact` | 💥 | 角色、物品、场景 | 瞬间，pulse | 一次局部闪光/冲击精灵，不做物理破坏，也不自动推断伤害 |
| `wet` | 💧 | 角色、物品 | 持续，start / stop | 水滴图标或预制湿润覆盖层，不生成新贴图 |

全局地图只把相关效果聚合到地点活动标记，避免铺满人物表情；放大后挂到对应实体锚点，室内目标不在外部街道冒出特效。目标只有文字资料、没有视觉锚点时，在实体资料旁显示 emoji；不能猜测坐标。焦点人物最多突出一个瞬间表情，其余按效果表优先级合并，避免遮挡阅读和场景入口。

**来源与边界**：燃烧等世界效果来自已确认的结算结果，不能从 `npc_decided` 的行动意图直接触发。“想点燃桌子”没有 🔥；“内心愤怒但面无表情”没有地图上的 😠。`angry_expression` 只标注已描述的外显表情/行为，不从 SAN、关系记忆或其他人的猜测推断情绪。视觉标签不注入角色感知/记忆，不改变其认知；沙盘仍是观察者画面，角色阅读栏仍只显示原有感知、决定与记忆。

**生命周期**：start 按 `(targetId, effect)` 幂等开启，stop 关闭，重复 start 不叠加多个火焰；不同效果可共存。pulse 的播放时长和动画参数由效果表固定，不由模型任意指定。持续效果跨拍、跨 LOD 和空间切换保留，直到显式 stop、绑定的既有状态到期或目标销毁；目标换地点时效果跟随目标，旧位置不残留。模型生成的持续效果在后续已有结算上下文中以精简列表提供，以便在解除时输出 stop，不为检查效果是否结束额外唤醒模型。已有结构化状态明确结束时由代码清理，不做文字语义推断。

**文字优先**：未知标签、非法目标、无关来源或错误操作只丢弃对应视觉注释，记录诊断，不拒绝本来合法的整拍结算、不触发模型修复调用。前端仅处理允许列表，不能根据模型输出执行代码或加载任意素材地址。缺少预制特效时用表内 emoji，缺少标签时展示原文字；视觉注释不覆盖实际 HP、物品存在性、通行状态等权威数据。

标签历史与有效状态随整拍提交保存（第 5.5 节）。首次打开、进入房间、断线补帧与回看直接恢复该分钟的持续效果，不重播过去的 pulse；实时观看的新拍才播放瞬间效果。旧历史未记录标签时表示“无视觉效果记录”，不能调用模型补标签或借用当前效果。

## 4. 聚焦态：分屏

**浏览空间与聚焦人物是两个独立状态**。放大地图和点击场景可以只浏览画面，不强制打开人物阅读栏；进入房间后点击人物才聚焦。右侧未聚焦人物时，场景资料入口可查看该地点的当前段落、物品和出口。

点局部/室内的一个人物（或摘要流的一条、或段落里的人物链接）：

1. 根据所选快照定位角色：在路上则聚焦对应道路，在室外则聚焦局部场景，在室内则作为导航捷径进入对应内部空间。沙盘在左半边（约 52%）重新取景，聚焦人物高亮并显示 `spot` 原文。
2. 右半边**滑入阅读栏**。历史链接保留目标时间；三级画面与阅读头部共用该快照，实时消息不覆盖回看中的空间。
3. 地图面包屑负责返回上一级空间；阅读栏关闭按钮只退出人物聚焦并扩大画布，保留当前位置。另提供“回到全局地图”。镜头过渡不会改变模拟时间或把角色移动到别处。

实时跟随所选人物时，其跨场景移动可更新当前空间；用户主动平移或浏览其他地点后暂停自动镜头跟随，保留人物阅读栏，提供“定位人物”按钮恢复。导航状态保存全局/局部镜头和当前房间，切换快照时重新校验所选角色是否存在。

### 4.1 阅读栏

头部：姓名、年龄、职业、所在地点；"正在：揉面团 · 第 3 分钟"（只有意图描述和已进行的分钟数）；HP / SAN / 疲劳三个量表。**头部随所选快照变化**：实时态读最新已结算快照，回看态读历史快照中的角色头部字段（第 5.2 节），并标明"回看"；缺少历史字段时显示"无记录"，不拿当前值补历史。

标签页：**此刻** · 档案 · 记忆 (n) · 关系 (n) · 随身 (n) · 这个地方。

**「此刻」是这个人的流**，按分钟向下排，最新在底部，"现在"贴底并跟着走。每一分钟的条目只有三种东西：

| 内容 | 来源 | 呈现 |
|---|---|---|
| 她读到的段落 | `npc_perceived.narrative` | 第一人称段落，引用标签渲染为链接。别人说的话由渲染器写在段落里，显示为引用块 |
| 她做的和说的 | `npc_decided`（新，第 5.1 节） | 左边框的块：意图描述一句；有原话则原话另起一行。continue 显示"继续 …" |
| 她记下的 | `npc_memory_changed`（新，第 5.1 节），按角色、操作发生的 tick 和游戏时间对上 | add 显示"记下：…"，replace 显示"改记为：…"，delete 显示"撤回：…"；relationship 类标出"关于谁"。同分钟多次操作按 `sequence` 排序 |

**这一栏永远不出现**：引擎的时长判定、技能门槛、骰子、结局判定、其他人读到的版本。想看别人眼中的同一分钟，点段落里那个人的链接：时间带不动，阅读栏切成那个人在同一分钟的流。

**折叠**：连续的"没变化"分钟（定义见 5.3）合并成一行，写清跨度，点"展开"逐分钟显示。本版不生成来去摘要：位置变化不能证明角色注意到了谁，也不从自由文本猜测结构化进出。角色实际读到的来去保留在原段落里。沙盘仍可显示客观位置，但不把它转写进角色阅读流。

**引用链接**：`[npc_*]` 点了切人并定位；`[item.*]`、`[SCN_*]`、`[ROAD_*]` 根据项目实体绑定定位对应层级并高亮，室内场景链接可直接进入对应房间。无视觉绑定时显示实体文字，不猜位置。`[stranger_*]` 别名对观察者解析为真人（第 5.1 节的 `aliases`），显示为"陌生人（Earl）"并可切人。

其他标签页取现有 `npc-statuses` 里的档案字段、记忆表、关系图、物品清单、当前地点的段落。这些都是当前值，不随时间带回拖；回看时统一标明"当前资料，不随回看变化"。`NpcMemory` 继续作为当前记忆的来源，但不用于还原历史阅读流或历史显著度。

## 5. 数据模型

### 5.1 新增落库行

都写进现有 `SimulationEvent` 表（`(sessionId, gameDateTime)` 已有索引，随会话级联删除），新增三个 `type`。历史关联以 `(sessionId, tick)` 为拍的身份，`gameDateTime` 用于时间定位和展示；游标使用 tick，不使用浏览器时间。

**`npc_decided`** — 每人每次决定一行，`gameDateTime` 是做决定的那一分钟（也就是感知那一分钟）。

```ts
data: {
  tool: "act" | "continue";
  description?: string;        // act
  utterance?: string;          // act，原话
  objectRefs?: { id: string; role?: string }[];
  skillId?: string;
  receipt: { accepted: boolean; actionId?: string; reason?: string };
}
```

被信任边界驳回且重试后仍被丢弃的 act 也落一行，`accepted: false` 带原因。写入点：`NpcActionController` 拿到 `ActionReceipt` 之后、`continue` 分支处。

**`npc_memory_changed`** — 每次成功的角色记忆操作一行，只追加。行上的 `gameDateTime` 是操作发生时刻，不是被修改记忆的原始时刻；`actorNpcId` 是记忆所属角色。

```ts
data: {
  operationId: string;         // 操作开始时生成，持久化重试复用；也作为事件 id
  sequence: number;            // 同角色同 tick 内的操作顺序
  source: "decision" | "consolidation";
  op: "add" | "replace" | "delete";
  memoryId: string;
  handle: string;
  before?: { type: string; content: string; targetId?: string };
  after?: { type: string; content: string; targetId?: string };
}
```

add 只有 `after`，replace 有 `before` 和 `after`，delete 只有 `before`。这些是当时的内容副本，不在读取时回查可变的记忆表。成功的 `writeMemory` 和角色主动整理记忆的 add / replace / delete 都覆盖；失败操作、访问次数更新和重要度衰减不生成此事件。操作台修改长期意图属于观察者操作，不伪装成角色自己记下的内容。

写入点在记忆持久化层：把操作时间、tick、sequence 和 source 从角色决策/整理上下文传入，**当前记忆的变更与对应事件写入使用同一数据库事务**；不得只在工具成功返回之后补写日志。按稳定的 `operationId` 去重，持久化重试不得重复修改记忆或新增事件。事件随会话清理，但不随单条记忆撤回而删除。对旧会话无法恢复已被覆盖或删除的原文，显示"此阶段无记忆操作历史"，不从当前记忆反推历史。

**`tick_record`** — 每拍一行，`actorNpcId: "system"`，`location: "global"`。

```ts
data: {
  schemaVersion: 1;
  previousSettledTick: number | null;
  perceptionFailures: string[]; // 本拍尝试渲染但失败的角色 id，不能折叠成安静分钟
  occurrences: {
    id: string;
    source: "engine" | "feature";
    actionIds: string[];
    actorId?: string;
    locationId: string;
    speech: boolean;
    utterance?: string;
    content?: string;
    targetIds: string[];
    perceivers: { characterId: string; clarity: "full" | "limited" | "trace" }[];
  }[];
  transitions: { actionId: string; actorId: string; from: string; to: string; reason?: string }[];
  damage: { characterId: string; field: "hp" | "san" | "fatigue"; delta: number }[];
  scripted: string[];          // 本拍触发的脚本事件 id
  visualEffectEvents: VisualEffectEvent[]; // 本拍生效的视觉注释，见第 5.5 节
  world: {                     // 本拍结束时的小状态，整份存，不做增量
    weather: Record<string, { type: string; intensity: number }>;   // regionId →
    blocked: string[];         // 被封的 connectionId
    visualEffects: {
      catalogVersion: 1;
      active: ActiveVisualEffect[]; // 全部持续效果，回看/重连直接恢复
    };
  };
}
```

**occurrence 来源必须与角色路由一致**：目前 `NpcActionController.processTickReport` 会把 `featureEvents` 转成合成 occurrence，但不回写 `TickReport.occurrences`。实现时提取一次性的规范化步骤，把引擎 occurrence 与这批合成 occurrence 合并、分配稳定且不冲突的 id；角色路由和观察者落库共用这份结果，不各自重新推导感知者。转换沿用现有规则，不新增模型调用；同一事件不得因两条来源重复计数。`scripted` 记录本拍实际触发的脚本 id，不能由是否存在引擎 occurrence 推断。

写入点：`SimulationRunner` 在 Applier flush、角色感知与决定、记忆操作全部完成之后，与 `npc_position_snapshot` 同处。`world` 每拍整份存的理由：区域和边的数量都很小，整份比"整点快照加增量重放"简单得多，回看时不需要重放。整拍发布边界见第 5.4 节。

**`npc_perceived` 补一个字段**：`data.aliases: Record<string, string>`，本分钟该视角的别名到真实 id 的映射。观察者靠它把 `[stranger_*]` 解析成人。

### 5.2 某一分钟的世界快照

`快照(T) = npc_position_snapshot(T) + tick_record(T).world`，并携带 `{ tick, gameDateTime }`。新快照的角色集合就是当拍存在的角色，包含已死亡者；死亡状态来自当拍角色字段，历史回看不混入后来注入的角色。旧快照可结合 `{ 死亡 ≤ T }` 降级展示位置。

扩充 `npc_position_snapshot.data`，保留现有 `positions` 和字符串形式的 `currentActions` 以兼容现有消费者，新增：

```ts
characters: Record<string, {
  name: string;
  age?: number;
  occupation?: string;
  locationId: string;
  locationName: string;
  hp: number;
  maxHp: number;
  san: number;
  maxSan: number;
  fatigue: number;
  isAlive: boolean;
  action: {
    actionId: string;
    description: string;
    progressMinutes: number;
  } | null;
}>;
```

这些字段在当拍角色决定结束后、发布前从同一状态采样。`action` 只取引擎中已经 active 的动作；刚提交但未开始的意图留在 decision 条目，不显示为"正在"。`progressMinutes` 直接取动作运行态，不按描述字符串或浏览器经过时间推算；不返回判定时长、技能门槛等引擎内部字段。扩充 `npc-statuses` 返回 `fatigue` 与同结构的 `action` 供当前资料使用，但历史头部只读快照。

### 5.3 推导（纯函数，服务端）

- **某人某分钟是否"没变化"**：仅对记录完整的已结算拍计算；该人不在 `tick_record(T)` 完整 occurrence 集合的任何 `perceivers` 里，且 `npc_decided(该人, T)` 不存在或 `tool = continue`，且该分钟没有该人的 `npc_memory_changed`。缺行、渲染失败或旧数据覆盖不足的分钟不得推断为安静分钟。
- **折叠边界**：只合并游戏时间连续、记录完整且 `quiet = true` 的分钟；不跨越缺失记录或未知历史。角色流不返回由位置快照推导的 `presence`，也不生成来去摘要。
- **密度(T)**：`tick_record(T)` 所有 occurrence 的 `perceivers` 并集大小。
- **显著度**：对完整集合中的每条 occurrence 打分，基础 1；`speech` +2；感知者每多一人 +1，上限 +4；所引动作有 `to ∈ {failed, interrupted}` 的 transition +3；任一感知者本拍有 `hp` 或 `san` 负向 damage +3；本拍有脚本事件 +3；任一感知者本分钟的 `npc_memory_changed` 为 add / replace 且 `after.type` 是 `secret` 或 `relationship` 时 +1。一分钟的分数取其最高的 occurrence，没有 occurrence 时为 0。后续记忆修改或撤回不改变过去的分数。
- **摘要**：给定 `[from, to]`，取分数最高的 N 分钟按时间排序，N = `clamp(6, 跨度分钟数 / 30, 12)`。每条：时间、当事人（最高分 occurrence 的 `actorId`，没有则第一位感知者）、标题（该 occurrence `content` 的第一句；`speech` 行用"X 对 Y 说了……"的形式，不引原话）。**这是整个界面唯一出现引擎客观段落的地方**，作索引用。

### 5.4 已结算边界与持久化

`tick_record` 同时是该拍观察者数据完整的提交标记。感知、决定、位置/角色快照、其余拍内事件、运行时存档及 `tick_record` 在最后一个数据库事务中提交；此前记忆操作已按第 5.1 节与当前记忆逐操作原子提交。最终提交前检查该拍记忆操作均已完成。所有新增观察者 HTTP 查询只能读取有提交标记的拍，提前落库的记忆事件也必须经过这个条件过滤。

同会话每 tick 只允许一个提交标记，使用由 `(sessionId, tick, type)` 派生的稳定事件 id 实现幂等。最终事务失败时不得推进已结算游标、不得发送 `tick_settled`，暂停并报告原因；内存状态和部分已完成的记忆操作不能当作完整历史发布。恢复后沿用已有 tick 编号，不复用失败 tick；允许编号有空洞，由 `previousSettledTick` 串联成功提交的拍，失败拍显示为缺失记录，不视为安静。此规则保证观察者不会读到半拍，不承诺对整个引擎运行做事务回滚。

`tick_settled` 只在事务提交后发送。提交成功但广播失败时不回滚，客户端用已提交游标补齐。握手、HTTP 和广播都读取同一个持久化已结算边界，不能直接使用尚在推进中的 `dgsm.getGameDateTime()`。

### 5.5 视觉标签契约与保存

在已有结算的最后一个输出阶段增加可选 `visualEffects` 注释数组，不新增结算阶段或独立调用。例如，同一次结算确认灯具开始燃烧后，可附带：

```json
{
  "visualEffects": [
    {
      "sourceActionId": "action_123",
      "targetId": "item.lamp",
      "effect": "burning",
      "op": "start"
    }
  ]
}
```

模型只能引用本次已结算的来源动作和实际相关实体。绑定已有 occurrence 时由代码关联其 id，不让模型猜代码尚未生成的 id。确定性子系统与脚本可直接附带同类标签；已确认的 speech occurrence 可由代码产生 speaking pulse，与模型重复的同源标签去重。没有结算模型调用的空拍不为视觉标签补调用。

视觉注释与核心结算字段分开解析：注释字段允许省略，省略等于无新增指令，不表示关闭已有持续效果。逐条执行效果表、目标类型、目标存在性和本拍来源引用的结构校验；错误条目丢弃，不进入核心结算的拒绝/修复路径。模型负责在已有文字判断中选择合适标签，代码只校验协议和已有结构化事实，前端不再进行自然语言判断。

通过校验并随整拍提交的标准化类型如下；`id`、对象类型、地点、时刻由代码补齐：

```ts
type VisualEffectName =
  | "burning" | "speaking" | "angry_expression"
  | "sleeping" | "impact" | "wet";

type VisualEffectEvent = {
  id: string; // 由 sessionId、tick、来源和稳定序号生成，持久化重试复用
  targetId: string;
  targetKind: "character" | "item" | "scene";
  locationId: string; // 事件发生的地点，由后端解析，前端不猜
  effect: VisualEffectName;
  op: "start" | "stop" | "pulse"; // 允许的操作由效果表约束
  source: { kind: "action" | "occurrence" | "feature"; id: string };
};

type ActiveVisualEffect = {
  targetId: string;
  targetKind: "character" | "item" | "scene";
  locationId: string; // 当拍目标所在位置；转移时更新，销毁时删除
  effect: "burning" | "sleeping" | "wet";
  startedAt: string; // 游戏时间
  sourceEventId: string;
};
```

服务端用纯函数按既有持续效果和本拍指令更新有效集合；同目标同 effect 的 start / stop 按标准化序号处理，最后一条有效指令决定当拍结果，pulse 不进入持续集合。只有存在明确的既有条件绑定时才随其到期清除，不能根据文本猜过期时间。作用于已销毁目标的 start/pulse 丢弃，已有持续效果清除；标签只改变视觉状态，不创建真实火灾伤害、光照规则、睡眠状态或新的世界实体。

`tick_record.data.visualEffectEvents` 保存当拍指令，`world.visualEffects.active` 保存当拍结束时完整持续集合，二者与第 5.4 节提交标记原子落库。恢复 runner 时从最后提交的集合加载，不能只保存在某个浏览器或当前加载的场景里。失败拍的临时视觉状态丢弃，不推进到下拍；首拍默认空集合，只有项目已明确配置的初始效果可播种。旧记录缺少 visualEffects 表示覆盖未知，与新记录中的空 active 数组区分。

minute 接口通过 world 返回所选拍的持续效果；`tick_settled` 额外带本拍 visualEffectEvents，客户端通过事件 id 和第 7 节实时/补帧状态决定是否播放 pulse。无需新增视觉效果查询接口，也不增加第四种 SimulationEvent 类型。视觉标签不单独增加密度、摘要分数或角色流条目，避免把同一件事因特效再计一次；映射表以 catalogVersion 固定语义，未知版本保留文字而不猜效果。

## 6. 接口

新增三个读接口（挂在 `mapRoutes` 之后，路由显式应用鉴权和会话所有权中间件，不能只依赖挂载顺序）。角色接口额外校验角色属于该会话。它们只读第 5.4 节已提交的记录。

共同参数：普通时间查询使用 `from` / `to`（含端点）及 `throughTick` 上界；补帧使用 `afterTick` / `throughTick`，范围为 `(afterTick, throughTick]`。时间范围与补帧范围二选一。`throughTick` 固定为订阅握手或聚焦确认返回的已结算游标，翻页期间不随新拍移动。首次无游标时 `afterTick = 0`；此处 tick 从 1 开始，0 表示未结算任何拍。限制每页大小，返回不透明的 `nextCursor`（末页为 null）和 `complete`；后续通过 `?cursor=...` 读取同一接口。分页游标保留原查询范围、throughTick、角色和页内位置，并绑定当前用户/会话；不能通过改变 afterTick 缩小原摘要范围，也不能静默截断。

| 接口 | 返回 |
|---|---|
| `GET /api/simulation/:id/timeline?from&to&throughTick`，或 `?afterTick&throughTick` | `{ throughTick, settledTicks: {tick, previousSettledTick, gameDateTime}[], density: {tick, gameDateTime, count, locationIds}[], digest: {tick, gameDateTime, score, actorNpcId, actorName, locationId, headline}[], nextCursor, complete }`。即使密度为零也返回该拍的 `settledTicks`；`locationIds` 是完整 occurrence 集合所在的地点，沙盘用最近 10 个游戏分钟的并集决定哪些地点发亮 |
| `GET /api/simulation/:id/minute/:gameDateTime?throughTick` | 第 5.2 节的快照。只匹配不超过边界的已结算记录；没有快照时返回明确的缺失状态，不用当前状态替代。握手还返回最新已结算时间，客户端用它定位首屏 |
| `GET /api/simulation/:id/characters/:npcId/stream?from&to&throughTick`，或 `?afterTick&throughTick` | `{ throughTick, entries: {tick, gameDateTime, narrative?, aliases, decision?, memories: MemoryChange[], recordStatus: "complete" \| "render_failed" \| "legacy_incomplete", quiet: boolean}[], nextCursor, complete }`。`MemoryChange` 包含事件 id 和第 5.1 节记忆操作字段；不从 `NpcMemory` 补历史 |

折叠在客户端做（根据 `quiet`、`recordStatus` 与时间连续性），不返回 `presence`。历史游标页的 digest 在整个固定查询范围选取 top N，而非每页分别选 N 条；分页只切分返回数据，不改变摘要范围。旧会话没有提交标记的记录走显式的历史降级读取分支，标明覆盖不足，不作为新协议的完整已结算拍。

### 6.1 Socket 鉴权与订阅

现有 `WebSocketManager` 的 `type=simulation` 分支会在鉴权前注册观察者，**实现时必须移除这个提前注册/返回路径**。连接先验证有效凭证和会话所有权，通过后才能注册、读取订阅游标或发送任何会话数据；缺失/过期凭证与非所有者连接关闭，HTTP 对应返回 401 / 403。凭证沿用应用现有认证机制，禁止把凭证写入日志。长连接在凭证过期时关闭，重连重新鉴权。`focus` 还要验证角色属于该会话，非法请求不改变当前订阅。现有公共地图接口不因此自动获得私密角色流。

服务端为每个已鉴权客户端保存 `{ sessionId, focusedNpcId, focusRevision }`；同会话多个客户端互不覆盖。客户端发送 `{ type: "subscribe", npcId?: string }`。服务端先注册该连接的事件缓冲，再在同一会话发布锁内读取已提交边界、发送 `{ type: "subscribed", sessionId, settledTick, settledGameDateTime, state, settling, focusRevision }`，然后排出边界之后的消息。保证注册、取边界与拍发布之间没有漏帧窗口。尚无提交拍时 `settledTick = 0`、`settledGameDateTime = null`，显示"等待首拍"。

**实时消息**：每拍提交后向订阅者推一条 `tick_settled`，含 `{ sessionId, tick, previousSettledTick, gameDateTime, focusRevision, focusedNpcId }`，以及该分钟快照、`visualEffectEvents`、density、摘要候选（若分数 > 0）和当前聚焦者的 stream 条目。快照中的 `world.visualEffects` 是持续效果的恢复来源，`visualEffectEvents` 按第 5.5 节控制实时瞬间表现。无聚焦者则不带 stream 条目；角色不在该拍角色集合内时明确返回空条目。条目形状与 HTTP 一致。只向对应客户端发送聚焦者条目，不把所有 `npc_perceived` 或记忆操作追加到现有全员广播中。

客户端切人发送 `{ type: "focus", npcId: string | null, requestId }`；null 表示退出聚焦。服务端在同一发布锁内更新该连接的聚焦者和递增 `focusRevision`，返回 `{ type: "focus_ack", requestId, npcId, focusRevision, settledTick, settledGameDateTime }`，之后的 tick 携带新版本。客户端立即停止把旧人物条目写入当前阅读栏，按确认边界补取新人物的所需历史，再合并确认之后缓存的对应版本条目。快速切换时仅采用最新 requestId 的确认与 HTTP 结果；旧版本可更新全局快照，但不能串入新人物阅读流。

运行/暂停和是否正在结算由 `simulation_status` 消息发送，带会话内单调递增的 `statusRevision`；订阅确认同时返回其当前值。HTTP 补帧不覆盖较新的状态消息。状态消息不推进已结算游标。

操作台复用现有接口：`pause / resume / step / stop`、`config`（天气）、`characters`（注入）、脚本事件。

## 7. 实时与追赶

### 7.1 时钟与暂停

- "现在"是最新已提交拍的游戏时间，由订阅确认、受边界约束的 HTTP 和 `tick_settled` 共同确定。浏览器时间只计算离开时长，不推算模拟进度。时区或客户端时钟偏差不能改变游戏分钟。
- 一拍开始时服务端发送 `settling: true`；顶栏保留最后已结算的时间并显示"结算中"。例如 14:32 之后的一拍正在执行，显示"14:32 · 结算中"，提交后才显示 14:33。仅墙上时钟跨分钟不触发状态变化。
- 暂停请求按现有 runner 语义让当前拍先结束；暂停后时间冻结，显示"暂停"。恢复从该游戏时间继续逐拍推进，不跳到墙上时钟、不补造暂停期间的分钟。单步只推进实际执行的拍数。
- 一拍的模型调用需要几秒到几十秒是正常延迟；超过一分钟也不并发启动追赶拍。停机恢复后同样从持久化游戏时间继续。运行中的会话不自动再次调用 `enableRealTimeSync` 重设时间，避免历史时间重叠。
- 回看态顶栏显示所选游戏时间和"回看"；实时订阅继续缓存和更新最新边界，不能把沙盘或头部强行推回现在。

### 7.2 首次加载、补帧与重连

1. 按用户、会话读取本地上次查看游标，先建立已鉴权 Socket 并 subscribe；握手前也缓存消息。收到 `subscribed` 后固定边界 H，后续实时拍先缓存。
2. 拉取截至 H 的 timeline（首次为游戏当天，返回访问为上次游标之后）、H 对应的 minute 快照，以及聚焦角色所需范围的 stream。分页读完固定边界，再安装同一边界的数据。无首拍时保持等待状态；没有本地历史缓存时，为当天时间带和阅读窗口另拉截至 H 的范围，不能把本地游标当作已缓存完整历史的证明。
3. 按 tick 合并 H 之后缓存的实时消息，重复拍幂等覆盖；通过 `previousSettledTick` 检查是否接上本地边界（首拍的 null 对应未结算的 0），而不是要求整数 tick 连续。断链时暂停推进客户端游标，从当前边界重新握手补帧。聚焦流另按 npcId / focusRevision 管理覆盖范围，全局快照的进度不能代表新聚焦者已补齐。
4. 仅在查询范围全部加载完成、消息链完整合并后更新同步游标。"上次查看"游标在页面可见且数据已显示时更新，作为下次摘要起点；后台收到了数据不代表用户看过。两类游标按用户和会话隔离。
5. 断线显示"连接中断"并保留最后画面，不按墙上时间伪造进度。重连重新握手取得 H，走同样的固定边界补帧与合并流程；新建连接时重新声明聚焦角色。提交后广播丢失的拍由 HTTP 补回，不依赖服务端内存消息历史。

## 8. 错误处理

| 情况 | 处理 |
|---|---|
| 一拍被引擎整体拒绝（无变化） | 时间带上标空拍记号；不补、不猜 |
| 观察者整拍提交失败 | 不发布该拍、不推进已结算游标；暂停并报告原因。已有部分记忆操作不作为完整历史返回；恢复后的编号空洞显示为缺失记录 |
| 模拟器因重复错误自停 | 顶栏显示暂停与原因；操作台可继续 |
| 某人某分钟渲染失败 | `perceptionFailures` 记录角色 id，stream 返回 `recordStatus: "render_failed"`、`quiet: false`；条目写"这一分钟她没有留下记录"，不折叠成安静分钟 |
| 引用指向的物品已不在 | 链接照常渲染；后端确认已不在时提示"已不在这里"，不根据场景加载失败推断物品消失 |
| 场景资源未制作、加载失败或没有实体视觉绑定 | 保留简化地图或上一级画面，显示明确占位、文字资料和重试入口；不把缺素材当成空房间，也不阻塞阅读流 |
| 快速缩放或切换场景时旧资源迟到 | 按导航版本丢弃过期切换结果，缓存策略可保留资源，但不能覆盖当前空间或镜头 |
| 视觉标签未知、目标非法、生命周期不匹配 | 丢弃该注释并记录诊断；不拒绝合法结算、不额外调用模型，文字正常展示 |
| 标签合法但尚无对应预制特效 | 使用效果表内的 emoji 回退；无对象锚点则放在实体资料旁，不猜坐标 |
| 旧快照没有视觉效果集合 | 标明“无视觉效果记录”，不使用当前效果或重新调用模型补历史 |
| 回拖超出范围 | 钳制到会话开始与最后结算分钟之间 |
| 快照缺行（历史会话未落 `tick_record`） | 沙盘只画已有位置，天气、封路与缺失的历史头部字段显示"无记录"；返回历史覆盖不足，不用于推断安静分钟 |
| 历史会话没有记忆操作事件 | 显示"此阶段无记忆操作历史"；当前记忆标签页仍可用，但不反推过去的记忆内容 |
| HTTP / Socket 鉴权失败或凭证过期 | 停止订阅，提示重新登录或无权访问；不能降级到公共 Socket 获取角色流 |
| HTTP 补帧失败、乱序或缓存消息接不上游标 | 保留已完整显示的数据与游标，重试握手和补帧；不跳过缺口 |
| 自定义字体未加载完 | 使用系统中文字体回退（`font-display: swap`），不阻塞文字阅读 |

## 9. 测试

- 5.3 的安静判定、密度、显著度与摘要是纯函数，单元测试；客户端折叠边界另测。夹具从一次真实运行落库的行里截取，并补齐下列边界场景；不以已有 60 拍恰好没出错代替覆盖。
- **记忆历史**：T1 add、T2 replace、T3 delete 后，T1 原文不变，T2/T3 各显示当时的修改/撤回，当前记忆已删除；同分钟多操作排序稳定，后续操作不改过去分数。覆盖整理记忆、操作失败不产生日志、事务失败同时回滚记忆与事件、相同 operationId 重试不重复写，以及旧会话不反推历史。
- **完整感知事件**：只有 feature/scripted 合成 occurrence、没有引擎 occurrence 的拍，角色路由与落库的 perceivers 一致，密度与摘要可见，continue 且不写记忆也不会被折叠；同一事件不重复计数。
- **视角与折叠**：某人客观进出但聚焦角色未感知，阅读流不能出现位置推导的来去；实际读到的进出保留原段落；渲染失败、缺行和旧数据不足不折叠。
- **接口与访问控制**：三个读接口在种子会话上做集成测试；HTTP 和 Socket 都覆盖未登录、过期凭证、其他用户、其他会话角色。两位客户端聚焦不同人物互不覆盖；公共模拟器入口不能绕过角色流的所有权校验。
- **订阅与一致性**：用可控同步屏障分别让一拍提交在握手注册前后、HTTP 各请求之间、分页期间；再覆盖重复/乱序消息、提交后广播丢失、断线重连、快速切人及迟到的旧 HTTP 响应，验证最终没有漏拍、重复条目或人物串流。最终持久化事务失败时没有提交标记和 `tick_settled`，HTTP 也读不到半拍；允许失败 tick 编号空洞，按 previousSettledTick 检查链条。
- **时钟与头部**：用假时钟覆盖暂停多分钟再恢复、单拍超过 60 秒、单步、停机恢复、浏览器时区/时间偏差。结算状态只来自服务端，未提交不推进时间；回看头部使用当拍 HP/SAN/疲劳、地点和 action.progressMinutes，缺失字段不借用当前值，新注入角色不出现在过去。
- **空间导航与 LOD**：全局不加载/绘制建筑细节；放大只展开可见区域，缩放阈值附近不反复切层；改变窗口尺寸或开合阅读栏后投影尺寸判断正确。继续缩放不能自动进入内部，点击入口才进入，返回恢复原镜头；多房间、室外场景、人物/引用导航捷径均按实际 id 定位。
- **资源生命周期**：快速缩放与切换地点不会被旧加载结果覆盖；室内加载失败时保留可用画面和文字；重复进出场景后 GPU 资源与缓存受设定上限约束。隐藏区域不继续运行无用动画，共享纹理不会被提前释放。
- **文字优先与轻量变化**：未覆盖的动作、外貌和新物品仍能完整阅读；导航、结算与描述更新不触发额外模型调用或图片生成请求，标签只随已有结算输出。场景加载和提示动画不阻塞阅读；已有视觉绑定的状态正确更新，补帧/回看不重复播放提示，无历史字段不借用当前状态。
- **视觉标签**：覆盖六种 effect 的目标类型与操作允许列表、未确认意图不触发、内心愤怒不生成外显表情、同源 speaking 去重、start 幂等、stop 清理、pulse 按事件 id 只播一次。同拍先 start 后 stop、跨 LOD/跨场景保留、目标移动/销毁、绑定条件到期、提交失败后的临时状态丢弃、重启恢复持续效果均测试；历史/补帧不重播 pulse，旧数据未知不当作当前状态。未知标签或不合法注释不触发结算修复，确认不增加模型调用次数，且不修改 HP、物品存在性和通行等真实状态。
- 组件测试：引用变链接（含别名解析与跨层定位）、折叠、时间带的分钟与像素换算、后台同步不更新上次查看游标、关闭阅读栏保留空间。以上协议与状态测试使用假服务端/假模型，不调用真实模型。
- **回放模式**：录一次真实的 60 拍运行，导出落库行为 JSON 夹具（`client/src/observer/fixtures/`），前端可以脱离服务端直接吃夹具运行。开发界面不打模型，不花钱。不做打真实模型的端到端测试。
- **视觉样板与验收**：先完成一张可缩放的简化全局地图、一个有外观的局部地点和一个可点击进入的室内，配像素角色、昼夜光照与阅读栏。用同一录制快照验证“全局 → 放大显现场景 → 点击进入室内 → 返回”的完整流程；再扩展本项目其他地点。检查昼夜与雾下的文字/入口可读性、缩放中的像素闪烁、人物遮挡及回看一致性；在作者实际开发设备记录首屏、场景加载时间和帧率，再确定贴图、阴影和后处理预算。

## 10. 落地与范围

**服务端**：`src/roleSim/` 提取供角色路由与观察者共用的 occurrence 规范化步骤，传递记忆操作上下文并报告渲染失败；`src/memory/` 为成功的角色记忆操作原子写入 `npc_memory_changed`。`src/simulation/` 写入 `npc_decided`、`tick_record`，补 `aliases` 和历史角色头部快照，实现整拍提交边界；`src/simulation/observer/` 放 5.3 的纯推导及已结算查询。`client/server/simulation/observerRoutes.ts` 提供三个有所有权校验、固定边界和分页的读接口；`mapService` 的当前 npc-statuses 补 fatigue 与 action。`WebSocketManager` 修复模拟器连接鉴权，增加 subscribe / subscribed、tick_settled、focus / focus_ack 与 simulation_status，实现每客户端聚焦、发布锁和游标补帧契约。同步事件类型声明与持久化过滤规则，私密感知/记忆事件不进入现有全员广播。复用现有节奏调度，不把游戏时钟改为墙上时间。

**视觉注释接入**：在 `src/engine/resolution/` 已有结算最后阶段的 schema、提示与解析中加入可选 visualEffects 注释，不增加阶段、调用或动作种类。`src/simulation/observer/` 增加效果类型允许列表、注释规范化和持续集合更新的纯函数；通过 TickReport 将合法标签交给 runner，随 tick_record 原子保存，并纳入重启恢复与 tick_settled。此改动只提供视觉注释，不让效果集合参与引擎判定。

**前端（替换）**：新目录 `client/src/observer/`：`ObserverPage`（布局）、`TopBar`、`Sandbox`（R3F Canvas）、`MapBreadcrumbs`、`TimeRibbon`、`DigestRail`、`ReadingPane`（含标签页）、`OperatorDesk`（包装现有 ConfigPanel / ControlPanel）。`scene/` 放 `WorldOverview`、`LocalArea`、`InteriorSpace`、`CharacterSprite`、`CameraRig`、`DetailController`、`SceneResources`、`Lighting` 与 `PostEffects`；`project/` 放专用场景配置、相机预设和实体绑定，美术资源按全局/局部/室内分包。hooks：`useTimeline`、`useMinuteSnapshot`、`useCharacterStream`、`useLiveTick`、`useSceneNavigation`；纯函数：`fold.ts`、`citations.ts`、`ribbonScale.ts`、`detailLevel.ts`。路由 `/simulation/:sessionId` 指向 `ObserverPage`。

`project/effectCatalog.ts` 保存 effect 到 emoji、表现优先级、瞬间时长和预制资源的固定映射；`scene/EffectLayer.tsx` 挂载目标效果，`useVisualEffects` 从快照恢复持续集合并管理实时 pulse 去重。效果层读取所选时间及当前 LOD，不自行维护另一份世界事实；地图上尚无可挂载素材时可只显示 emoji。

**依赖**：新增 `three`、与 React 18 匹配的 `@react-three/fiber` 8 及兼容的 `@types/three`；按实际使用引入 Three.js addons。原手绘专用依赖不安装。Phaser 消费者替换完成后移除 `phaser`，不在新场景接通前删除可用旧页面。

**删除**：`SimulationPage.tsx`、`components/simulation/` 下的 `TownScene.ts`、`InteriorScene.ts`、`PhaserContainer.tsx`、`WeatherOverlay.tsx`、`SidePanel.tsx`、`NpcCard.tsx`、`NpcDetail.tsx`、`SceneInfoPanel.tsx`、`EventLog.tsx`、`GameClock.tsx`。保留 `ConfigPanel`、`ControlPanel`、`SimulationSelectorModal`。

**Godot**：`godot-client` 原样保留，不接本设计。本次 HD-2D 沙盘使用浏览器 Three.js，阅读、超链接和操作界面保留 React，不同时维护两套新画面实现。

**实施优先级**：先用录制数据打通文字阅读、时间与实体导航；再完成三级地图的预制视觉样板，接通六种视觉标签，优先用 emoji 验证生命周期与回看；之后逐个替换为预制火焰、气泡等效果，扩展本项目地点；最后按收益加入少量物品状态与光影细节。任何动作或实体缺少专属画面时，文字路径仍必须完整可用。

**不在范围内**：玩家模式；通用模组适配、通用素材库与皮肤系统；运行时按文字生成模型/贴图/场景；开放动作的逐项动画、实时破坏与物理模拟系统；全部建筑内外物理连续的无缝世界；室内布景与地点描述文字的历史还原；引擎判定 / 调试抽屉；多观察者在场提示；暂停后的墙上时间追赶；从自由文本提取角色来去摘要；旧会话被覆盖/删除记忆的历史恢复。

## 11. 决定记录（2026-09-05 起，含后续修订）

1. 第一用户：观察者兼实验员；玩家模式以后再做。
2. 时间关系：按真实分钟节奏运行的活小镇；审阅修订后明确以已结算游戏时间为准，暂停与慢拍不跳时、不加速追赶。
3. 方向：沙盘 + 时间带 + 摘要流 + 阅读栏，共一个时钟；沙盘采用 Three.js HD-2D 画面。
4. 主屏：中间全局地图、底部时间带、左栏摘要；放大显现局部场景，点击场景进入内部，点击人物展开阅读栏。
5. 聚焦态：分屏（沙盘靠左、右栏阅读），否决浮层标注。
6. 阅读栏只有三种东西：她读到的、她做的和说的、她记下的；引擎判定一律不进；别人的版本靠切人看。
7. 流最新在底部跟着"现在"走；没变化的分钟折叠。
8. 摘要行用客观段落第一句作索引；回拖不还原地点描述历史。
9. 前端路径上不新增模型调用；开发用录制夹具回放。
10. 替换现有模拟页面，删 Phaser。
11. 用户最新决定：**只服务自己的项目，不考虑通用性**；允许专门制作场景与美术，撤销通用模组和零美术成本约束。
12. **视觉参考《八方旅人》的 HD-2D**：像素角色/贴图、立体场景、昼夜光影与克制景深；替代旧版程序手绘方向。
13. 技术栈：Three.js + React Three Fiber 渲染沙盘，React DOM 渲染阅读与操作界面；移除原 SVG/rough.js 方案及依赖计划。
14. Godot 客户端保留不动，留给玩家模式；观察者走 Web。
15. HTTP 和模拟器 Socket 均校验会话所有权；角色流仅发给该连接的聚焦者，多连接独立聚焦。
16. 历史记忆改读只追加的 npc_memory_changed，当前记忆仍读 NpcMemory；后来的修改和撤回不改写过去。
17. 角色路由与观察者落库共用包含 feature/scripted 合成事件的完整 occurrence 集合。
18. 先订阅、固定已结算边界、补历史、再合并实时消息；整拍提交后才能发布，按 tick 游标和 previousSettledTick 检查缺口。
19. 本版折叠只显示跨度，不从客观位置生成"她眼里的来去"；原段落保持角色实际感知。
20. 阅读头部跟随所选快照，新增历史状态和动作进度字段；其余当前资料标签页明确标注不随回看变化。
21. 地图采用三级浏览：全局隐藏建筑细节，缩放按区域展开局部细节，点击场景才进入内部空间；内部独立按需加载，返回恢复上一级镜头。
22. LOD 按屏幕投影尺寸及滞回阈值控制；空间导航、人物聚焦和实时/回看时间分别保存状态，共用稳定的实体 id 与所选快照。
23. 文字是核心，画面负责定位、导航与氛围；采用预制布景和轻量状态层，不实时建模、不逐拍生成美术。无法低成本可靠表现的变化由文字承担，不反向限制引擎的行动能力。
24. 已有结算可附带可选视觉标签，前端通过 effect → emoji / 预制效果查表表现；首版 burning、speaking、angry_expression、sleeping、impact、wet 六种，不增加模型调用。
25. 持续标签使用 start / stop，瞬间标签使用 pulse；效果事件与有效集合随整拍提交保存。回看恢复持续效果、不重播瞬间效果；标签错误不影响合法结算或文字阅读，外显表情不泄露未表现的内心状态。

## 12. Grayhaven 大场景先行原型（2026-09-06）

后续视觉制作以 [Grayhaven 艺术风格指导](2026-09-06-grayhaven-art-direction.md) 为准。该指导基于初代主创访谈与官方图像，将用户提出的“低饱和蜡笔画”转译为带粉蜡笔触感的手绘写实，并区分原作依据和本项目制作建议。

根据最新要求，先以 `testmods/grayhaven` 搭建可运行的全局环境，视觉参考改为《Life is Strange》的低饱和海岸小镇、柔和光照和怀旧色调。本原型不采用像素角色，不制作室内或局部场景细节；前文完整观察者系统与三级浏览仍属于后续工作，不作为当前原型已经完成的能力。

- **入口**：`/sandbox/grayhaven`，独立静态预览，无需登录或模拟服务；现有模拟页面保持可用。
- **内容**：模组 16 个户外节点与 19 条道路，包含主街、码头、灯塔、汽车旅馆、红杉林、旧锯木厂和雷德利站的外部轮廓。坐标为人工布置的示意地形，额外建筑和植被仅作布景；道路关系及步行时间来自模组，不能由画面距离反推。
- **浏览**：拖动和缩放地图，远景保留主要标注，放大后增加户外地点标注；点击地点定位镜头并显示模组地点手记。暂不进入室内，也不接人物、事件流、时间回看或 emoji 状态层。
- **画面**：静态地形、建筑体块和实例化林木，在载入时一次性构建；海面轻微变化。提供午后、落日、蓝调及海雾浓度预览，所有操作只影响画面，不改变游戏事实。
- **技术**：本阶段直接使用 Three.js + React DOM。暂不引入 React Three Fiber，不移除仍被现有页面使用的 Phaser。后续是否改用 Fiber 以实际场景管理需求决定。
- **素材边界**：目前是简化几何的大场景原型，尚未制作成套手绘建筑贴图；没有使用参考游戏的原作资产。继续坚持文字优先，不按模拟 tick 建模或生成美术。
- **数据维护**：`node scripts/export-grayhaven-sandbox.mjs` 更新静态导出；户外说明可以阅读，沿路室内场所只导出名称与引用。原型说明及检查命令见 `client/src/observer/grayhaven/README.md`。
