# 选择性日照调色与笔刷阴影：Godot 技术设计

版本 1.3 · 2026-09-08 · 状态：独立漫反射原型已运行，蓝鸟美术尚未接入

本文记录用户对蓝鸟街角测试的最新修正，供场景美术、技术美术和 Godot 开发共同使用。**大面积受限调色板，少数饱和色焦点；整体明度收敛，局部对比突出；真实投影定位，笔刷重新组织阴影形状。** 当前白天目标为大太阳晴天，不能用阴天的弱直射光替代。

本文补充并修正[通用油画场景渲染文档](painterly-rendering-godot.md)的调色与阴影方案。此前 Demo 的全局饱和度、对比度调整和 PCSS 截图属于历史试验，不是本文方案的实现成果。1.0～1.1 版仅交付设计。现已新增[独立渲染模块 v0.2](../../godot-client/rendering/painterly/README.md)与合成测试场景，蓝鸟模型、贴图和运行参数未因此改动。

**1.1 修订：** 明确笔刷遮罩先于增强、未遮挡阳光与环境／GI 分离、中性色连续处理、太阳低彩度衰减、表面流向与阴影拖尾解耦、作者重要度图，以及软压缩与最终输出色域映射。

**1.2 实现记录：** 独立线性深度捕获、接收面 `M0/Mp`、分离日照／环境输入、连续 Oklab 权重、流向／重要度接口和输出色域映射已经在测试几何上跑通。`M0/Mp` 当前在接收面计算而非保存为图块纹理；B 接受环境及外部间接光输入，未接入原生 GI 缓冲。局部对比首版为重要度控制的表面明度曲线；完整多尺度场景对比仍是后续目标。

**1.3 追加要求与实现：** 笔触重叠处少量积色加深；增加沿表面流向的断续毛刷纹理与笔锋分叉。v0.2 在有限笔触覆盖上计算颜料累积，作用范围限制在最终阴影内；不是把多次物理阴影相乘。边缘刷毛先进入 `Mp`，内部刷毛只做克制的颜料明暗变化。

## 1. 已确定的艺术规则

| 对象 | 目标 | 不采用的替代方法 |
| --- | --- | --- |
| 大面积颜色 | 道路、墙面、屋顶各有主色，大部分面积集中于相近的中间色域 | 全屏去色、再统一染黄 |
| 饱和度 | 当作稀缺资源，重点花在少数入口、招牌和局部材料颜色上 | 所有暖色同时变艳、所有暗色同时变灰 |
| 明度对比 | 通过大色面配色控制整体跨度；焦点与重要转折保留较高局部对比 | 统一降低对比，或对所有纹理锐化 |
| 日照 | 随太阳颜色选择性增强邻近色系，并受实际受光程度约束 | 阴影里的橙墙因颜色相近而自动发亮 |
| 暗部 | 保留天空／间接光带来的冷色和材料身份 | 主光颜色乘一个更小的亮度，或统一叠黑 |
| 阴影边缘 | 实边、断边、失焦边共同组成轮廓；主体笔触顺形体，阴影边缘拖尾有限响应光向 | 一圈等宽模糊、均匀锯齿或细碎噪点 |

“黑色笔刷色块”描述厚重、覆盖和拖刷形状；实际颜料目标以冷蓝灰、蓝紫灰等有色暗调为主。允许局部深暗，但不将所有投影合成为纯黑。

建筑本体的主要几何轮廓保持相对清楚，优先处理建筑投到地面的阴影及接地暗部。**地面阴影笔刷化不会自动消除建筑侧面与背景之间的几何轮廓**；建筑暗部轮廓融合需要后续单独的对象／边缘遮罩，本轮不以全屏模糊代替。

## 2. 按阳光邻近色选择性增强

### 2.1 光色、能量与正午退化

太阳物理照明色决定表面受光，美术权重决定增强多少。默认从太阳光色连续推导邻近色系，不靠按时刻硬切换的色相表。太阳颜色必须先与光能量分离，在固定参考亮度下计算色度；否则只改变能量也会改变色系匹配权重。

| 状态 | 直射光 | 选择性强调 | 阴影职责 |
| --- | --- | --- | --- |
| 正午近白光 | 明确而充足的日照 | 色相驱动的彩度增强随太阳低彩度减弱，保留明度与焦点对比 | 冷蓝／冷灰承托受光面 |
| 暖白日照 | 有限暖色倾向 | 黄、米白等邻近色得到克制强调，近中性色连续转为明度／光色响应 | 不同步染暖 |
| 夕阳 | 暖色、较低角度日照 | 红、橙等邻近色匹配更有意义，但效果仍受能量、遮挡、重要度和上限限制 | 保留蓝紫／冷灰 |

自动衰减是一条美术控制规则，不是物理模型保证的最佳曲线；必须检验整日变化是否有脉动。**只衰减基于色相的彩度强调，不把正午的明度强调和局部对比一起关掉。** 没有太阳贡献时，太阳增强归零；人工光规则另行设计。

这取代早期“正午始终强推黄色”的默认预设。若之后仍需额外强调正午黄色，可提供独立、连续且限幅的作者偏好，默认关闭，不以它绕开中性太阳的衰减。

### 2.2 连续的色系与中性色权重

以**完成基础与表现性材质合成、尚未接受日照染色的基色**判断材料所属色系。否则被阳光染暖的所有表面都会再次匹配太阳，造成重复增强。

在 Oklab／OkLCh 中计算色相和彩度，以线性 RGB 执行照明。Oklab 是近似感知均匀表示，不保证所有颜色完全等距；彩度也不等同于感知饱和度。RGB 输入按约定白点与颜色空间转换，不对数据纹理做 sRGB 解码。[Oklab 作者说明](https://bottosson.github.io/posts/oklab/)

下式定义设计权重，不是可直接复制的 Shader：

```text
I = 作者重要度（0～1）
F_color、F_light = I 经各自响应曲线得到的增强许可
D = 未遮挡太阳能量的平滑归一化 × max(dot(法线, 指向太阳方向), 0)
V = 1 − Mp（地面必须使用处理后的遮罩）
Cm = 基色在 Oklab 中的彩度
Cs = 太阳颜色归一到固定参考亮度后，在 Oklab 中的彩度
q(C; c0) = C² / (C² + c0²)，c0 > 0
qm = q(Cm; cm0)，qs = q(Cs; cs0)
H = 基色与太阳的圆周色相邻近权重（0～1）
G(Lm) = 按基色明度平滑保护近黑与高光的权重

有效彩度强调权重 = V × D × F_color × qm × qs × H
有效明度强调权重 = V × D × F_light × G(Lm)
近中性色的光色偏移权重 = V × D × F_light × (1−qm) × G(Lm)
```

- `H` 采用圆周最短色相距离与平滑衰减；原型可从 15°内完整匹配、15°至 65°降至零起调。`cm0`、`cs0` 是分别校准的彩度可信度尺度，不能直接套 HSV 的 S 值。
- 材料或太阳趋于中性时，`qm × qs` 连续消除不可靠色相的贡献。实现上安全处理零长度色向量；不能先除零产生 NaN，再指望乘零消除它。
- 近中性色不是硬 `if` 分支，也不是仅让原增强乘彩度后就宣称会自然变亮：明度和光色偏移是独立、连续混合的贡献。偏移使用太阳归一化后的 Oklab `a,b` 方向及幅度，近白太阳的偏移自然趋零，不给纯白光凭空添加黄色。
- 近黑与白色都可能低彩度，因此必须保留 `G(Lm)`；暗材质不因进入中性色范围而变白，浅色接近输出高光时增量平滑减弱。
- 上述 `V` 表示最终可见贡献的权重。实际合成应保留未遮挡日照，**对基础日照只乘一次 `V`**，避免已乘遮罩的缓冲又被重复乘暗；具体组织见 3.1 节。
- 玻璃、金属和其他特殊响应初版不做选择性重写。环境／GI 即使因暖地面反弹而很亮，也不进入太阳增强的受光判断。

### 2.3 作者重要度图与局部对比

每个地面图块／接收面增加一张作者绘制的单通道重要度图 `I`。黑色表示次要区域，白色表示重点；它表达作者判断，不能从总亮度、颜色饱和度或可交互状态自动推断。建筑可采用相同语义的表面遮罩。

`I` 以线性数据采样，通过四条**独立响应曲线**驱动局部对比、边缘清晰度、细节保留量、颜色增强上限。不能让一个白色区域同时无条件达到最艳、最锐、最硬。重要度低不等于删除所有细节，也不等于物理上不受光。

重要度图与 UV／图块坐标一起交付，记录分辨率、有效范围、扩边和过滤方式，相邻图块保持连续。缺图时使用低强调常量，默认普通表面 0.2、作者焦点可到 1.0；明确记录缺图，不偷偷从亮度自动生成焦点。接触保护、材质分类、接收有效区和玩法状态保持独立约束。

全局 `adjustment_saturation`、`adjustment_contrast` 保持 1.0，或关闭整组 adjustment。大色面配色与输出曲线控制整体跨度；焦点对比在阳光／环境合成后、输出色调映射前，按 `I` 对中尺度明度关系做克制调整。受光梯度可辅助识别转折，但不能替代作者重要度，也不能在阴影轮廓或对象边界附近制造锐化光晕。

正午的明度与焦点对比不受 `qs` 归零影响。颜色强调只修改受光分量；局部对比允许服务于暗部焦点，但不把它重新识别为太阳直射。曝光固定，不加全屏高通或统一锐化。

### 2.4 软压缩与输出色域

原型可从最大相对彩度增益 20%、最大感知明度增量 0.025 起调，通过重要度与上述权重控制。数值是未验证的设计起点，不是截图测量或硬截断值。

对艺术增量采用带平滑过渡的软压缩。正增量可参考 `delta_out = cap × tanh(delta_in / cap)`，`cap` 为正的允许增量，关闭效果时显式返回零；不要对所有原始颜色直接套 tanh，导致本来未超限的色板也被压缩。权重合法范围与数值安全仍可使用 clamp，禁用的是以 RGB 硬裁剪代替颜色设计。

色域边界取决于明度与色相，不能设置一个对所有颜色通用的固定彩度上限。增强阶段先软限幅；**合成、局部对比、曝光与色调映射之后，再检查目标 SDR sRGB 色域**，按固定色相、尽量保持明度的方向降低彩度到可显示范围。若明度本身已经越界，先处理明度，仅减彩度无解。不能把场景 HDR 中大于 1 的线性光值过早当作显示越界裁掉。

避免逐 RGB 通道裁剪引起色相偏移；检查高彩度黄、橙、蓝的渐变和色域边界连续性。该映射与前面的艺术软限幅是两个步骤，不能互相替代。[Oklab 色域映射讨论](https://bottosson.github.io/posts/gamutclipping/)

## 3. 独立阴影遮罩与绘画处理

### 3.1 选定路线及数据流

**采用独立遮罩路线。** 不把地面材质里扰动现有 `ATTENUATION` 当作最终方案，因为它难以控制原半影外的拖刷形状。Godot 的 `light()` 提供逐光衰减值，但这不等于向任意材质开放一张可自由采样的太阳阴影纹理。[Godot 4.7 Spatial shader](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/spatial_shader.html)

```text
固有色＋作者重要度图＋表面 flow map
  → 分别准备未遮挡阳光 S0、环境／GI 分量 B
  → 独立光空间捕获与接收面比较，生成物理遮挡 M0
  → 固定表面笔触＋有限响应光向的边缘拖尾，生成 Mp
  → 用 V = 1−Mp 共同约束阳光贡献与选择性增强
  → 合成 B 与调整后的阳光，再按重要度分配局部对比
  → 固定曝光／色调映射
  → 输出色域映射与 SDR 显示
```

两张遮罩都约定 0 为无阴影、1 为阴影，作为线性数据读取。**必须先得到 `Mp`，再进行太阳增强和最终日照合成。** 不能使用 `M0` 判断颜色增强，再用 `Mp` 覆盖；这会使外拖笔锋出现暖色毛边，内咬缺口与照明不一致。

阳光与环境／GI 的分离是计算和资产语义要求，不强制每个实时实现都分配两张完整纹理。同一 Shader 内可保留两个独立计算项；跨步骤或烘焙时必须交付可分别读取的通道，不能只存最终合成色，再试图从亮度拆回直射与反弹光。

| 数据 | 语义 | 约束 |
| --- | --- | --- |
| `S0` | 含材料响应、太阳能量与朝向，但尚未乘阴影的直射阳光项 | 即使原来被遮挡，也保留可重建的未遮挡响应；不包含 GI |
| `B` | 环境／GI 分量，含太阳间接反弹 | 不参与太阳色相增强；其他人工光、反射和发光另按原响应合成 |
| `M0`／`Mp` | 原始／绘画化遮挡 | 数据空间、含义和采样基准一致 |
| 受光元数据 | 太阳能量、光向、法线及未染色基色 | 判断直射与色系，不从合成亮度反推 |

```text
S_styled = 对 S0 的受光色系、连续中性色和限幅处理
L_precontrast = B + (1−Mp) × S_styled
```

此式限定为本轮漫反射研究的概念合成，未展开额外人工光、反射和发光。基础日照的可见度仅乘一次；2.2 节列的是最终有效增强权重，不意味着先乘一次遮罩再按此式乘第二次。`Mp` 侵蚀出缺口时，需要 `S0` 恢复那里的日照；原来已经被 `M0` 乘成零的颜色无法承担此职责。

只替换注册地面的太阳遮挡贡献；建筑本体继续正常受光和自阴影。GI 自身的空间遮挡不随笔刷边缘强行重算，这是局部绘画处理的近似范围，不宣称物理能量守恒。

### 3.2 捕获与接收

初版以 Godot 4.7 Forward+、固定正交主相机、单个太阳、静态建筑与室外地面为范围。独立光空间正交捕获跟随太阳方向；投影区域按世界包围范围固定，不能随着主相机平移／缩放改变笔触采样基准。

拟采用独立 `SubViewport`／专用捕获场景共享建筑网格与变换，以捕获材质输出明确约定的光空间线性深度。只注册有效遮光几何；玻璃、透明空隙、双面构件不能全部当作不透明盒子。接收阶段用世界坐标投到光空间做深度比较，保留 bias 的几何用途，不用它制造笔锋。

`SubViewport` 提供独立渲染目标与更新模式，**它不会自动交付所需的线性深度或最终阴影遮罩**。捕获纹理格式、精度、深度编码／解码、背景无命中值以及颜色链路旁路，都需用灰阶坡面与遮挡样本先验证。必要的 GPU 处理通过专用渲染步骤实现，不假定 Compositor 直接暴露原生太阳 shadow atlas。[Godot 4.7 SubViewport](https://docs.godotengine.org/en/4.7/classes/class_subviewport.html)、[Compositor](https://docs.godotengine.org/en/4.7/tutorials/rendering/compositor.html)

将接收结果映射到固定地面图块，保存有效接收范围。道路与抬高的人行道按实际高度重建接收点，不统一当作 Y=0；同一 XZ 位置存在桥面等多层接收面时必须分层，初版不支持这些区域。第一轮只注册室外道路、地块与人行道接收面；屋顶、墙面、室内、UI 不参与地面合成。

### 3.3 笔刷方向、尺度与边缘

主体笔触由每个表面的 **flow map** 决定，沿地面铺装、墙面木板或形体走向组织。静态场景锚定在世界／固定表面坐标；可移动对象锚定在对象表面并随对象变换，不能留在原世界位置。

流向图至少保存表面切平面内的二维方向，以线性数据读取，记录切线基准与有效区；过滤后安全归一化。无向笔触轴要处理 180°等价方向的插值，不能让相反向量平均成零；退化值使用作者指定的表面默认方向。原型采用对象 UV 或固定图块坐标，不用随太阳旋转的坐标采样整张颜料纹理。

**只有阴影边缘的羽化与少量拖尾响应光向。** 令 `d` 为阳光传播方向，水平地面用 `t = normalize(d.xz)` 控制边缘处理核；笔触底图、实例中心和随机种子保持固定。方向响应限定在可变形边缘带，强度和长度受重要度与接触保护限制，不让整片阴影内部纹理随太阳旋转。坡面后续改用自身切平面投影。

太阳接近垂直时地面投射方向退化：用水平分量幅度平滑衰减定向拖尾，沿用上一有效方向；无历史值时采用该表面 flow map 的方向。这样不会因一个几乎无定义的方位让拖尾突然旋转。仅固定种子不能保证无游动，仍须用连续变光向测试检查局部边缘响应。

以 `M0` 的边界距离定义可变形带，只在该带内侵蚀／扩张轮廓。原型笔刷长度取 0.4～1.2 米、宽度 0.08～0.25 米，早期轮廓位移上限 0.25 米；在约 23 米画幅下检验正常视距是否可读，再按实际资产校准。这些是早期设计起点，不是固定画风公式。用户进一步要求正常视距明显可见的向外笔锋与内缺口后，v0.1 默认改为 1.3 米长、0.24 米宽的主体笔触，外拖 0.9 米、内缺口 0.5 米，再按重要度与接触保护衰减；详见模块参数。

- 阴影主体保留连贯块面，内部有少量宽阔的颜料浓淡和断续露底；重叠笔触少量加深，并保留沿笔触走向的细刷毛。细纹随可分辨尺度减弱，不铺满各向同性噪声。
- 不规则笔刷遮罩包含长短不同的拖尾、缺口、干刷和偏心破边。程序噪声只辅助变化，不独自承担可识别笔锋。
- 通过重要度图派生的独立边缘响应曲线分配实边、断边和失焦边。重要转折／入口附近保留实边；次要的外缘允许较宽的破边与融合，不给整圈边界相同处理。
- 接地点附近约 0.1 米先设保护带，保留几何接触；笔刷化效果向外渐增，避免建筑看起来悬浮。保护带、笔锋和相邻图块采样必须有足够留边。
- “失焦”是局部边缘和相邻色面合并，不是模糊地面纹理，更不是模糊整栋建筑。

笔刷源图、表面流向图、作者重要度图与最终遮罩独立保存；后两者是正式作者输入，不从物理阴影或总照度自动推断。若后续生成或编辑笔刷图像，按图像生成工具流程制作；本次文档未生成任何笔刷资产。

### 3.4 合成与更新规则

地面原有底材、接缝和材料磨损继续存在。`Mp` 改变日照可见度，让冷色环境光成为暗部主要来源；阴影主体允许少量独立冷色偏移与浓淡变化，但不再叠一层与光照无关的透明黑片。

替换的是注册接收面的太阳遮挡项，不关闭整场景阴影，也不对太阳直射项和最终画面重复乘遮罩。墙、屋顶、未注册对象维持原阴影。接收面遮罩与可见深度限制必须阻止效果越过墙体、涂到招牌或覆盖前景物体。

相机平移／缩放不重建物理遮罩。几何或太阳方向变动时更新捕获与物理遮罩；只改变日照颜色时更新调色与合成参数；改变重要度图时更新其派生的边缘／增强权重，改变 flow map 时更新笔刷处理，均不无故重捕获物理深度。同帧或同步交换太阳状态与遮罩，避免新太阳配旧投影。静态预设切换先验证正确性，连续昼夜及动态遮光体另做更新成本与稳定性验收。

原型图块可从 2048²、约 32 米覆盖开始，保持捕获／处理图块的有效留边和纹素稳定；这不是性能保证。记录各步骤 GPU 时间与纹理内存后再选择正式分辨率，不默认每帧全量重建。

## 4. 实现边界与验收

### 4.1 后续工作顺序

1. 保存同机位晴天基线，关闭全局去色／压对比；交付作者重要度图与表面流向图，明确 UV／图块坐标及数据语义。
2. 分离并调试显示 `S0`、`B`、太阳受光元数据；只做独立 `M0`，验证投影、接收高度和变换同步，验证原阴影区也可重建未遮挡日照。
3. 显示 flow map、重要度、边缘带、保护区和 `Mp`，验证主体笔触固定、边缘拖尾有限响应光向。先完成晴天常用视距，再检查近景与平移稳定性。
4. 用 `Mp` 共同驱动日照与选择性增强，验证中性色连续过渡、太阳低彩度衰减、反弹光不误触发；再接入重要度局部对比、软压缩和输出色域映射。
5. 检查完整昼夜光色变化、遮罩同步、参数独立性，保存运行截图、调试通道和性能记录，更新 Demo 说明后再扩大接收面范围。

参数分为太阳状态、中性色／色系可信度、重要度及四条响应曲线、表面流向、捕获范围、笔刷尺度／种子、边缘／接触保护、软限幅与输出色域几组，提供独立开关与调试显示。实时／烘焙交付必须明确 `S0` 与 `B` 的职责。运行时现已提供 `PainterlyRenderer` 和 `PainterlySurface`，实际接口与限制以[模块说明](../../godot-client/rendering/painterly/README.md)为准；本文伪公式不是可直接复制的 GDScript。

### 4.2 必须检查的场景

| 测试 | 通过条件 |
| --- | --- |
| 同一橙色样本一半受光、一半背光 | 夕阳仅明显增强直射区域；背光保留冷色 |
| 仅被橙色地面反弹照亮的墙 | 即使 GI 很亮，也不触发太阳色相增强 |
| 原阴影被向外拖刷／向内侵蚀 | 无暖色毛边；缺口可恢复 `S0`，遮罩不会重复乘暗 |
| 白、米白、黄、红、蓝、灰、黑样本及连续近灰渐变 | 无硬分支跳色、NaN 或近灰色相抖动；近黑不变白 |
| 太阳彩度连续降至零、仅改变能量 | 色相增强平滑减弱，明度／焦点对比保留；能量不改变归一化光色色系 |
| 高彩度黄／橙／蓝与高光渐变 | 艺术软压缩与最终 gamut mapping 分别有效；无硬截断台阶、偏色和大块 RGB 裁剪 |
| 大面积赭色地面与小面积招牌 | 邻近色匹配不让地面抢走焦点；局部饱和色仍稀少 |
| 基色、物理光照、选择性增强开关对照 | 变化来源可识别；全局去色与统一锐化关闭 |
| 晴天／夕阳及连续光向变化 | 投影正确，主体纹理固定，只有边缘拖尾有限跟随光向；无双影和整体旋转 |
| 地面／人行道高度差与墙边接触 | 无悬浮、穿墙、接收偏移或多层误投射 |
| 原遮罩／笔刷遮罩对照 | 宽拖刷能在正常视距读出，主体仍连贯，实边和失焦边有区别 |
| 平移、缩放、窗口尺寸变化 | 笔触附着世界，尺度不随分辨率变化，无图块接缝和明显闪烁 |
| 太阳接近垂直及颜色单独变化 | 定向拖尾平滑减弱，无方向突跳；颜色变化不重捕获物理遮罩 |
| flow map 与重要度跨图块接缝 | 无方向抵消、采样游动或权重断层；缺图采用记录的默认值 |
| 单独改变重要度及四条响应曲线 | 对比、边缘、细节与色彩限幅可分别控制，不强制同时达到最大 |
| 未注册对象、UI、玻璃与屋顶 | 没有地面笔刷溢出；原材质响应和可读性成立 |
| 性能 | 分别记录捕获、边缘处理、合成耗时与纹理占用，不以单张截图宣称实时预算通过 |

**当前验证状态：** v0.2 的 50 项 GPU 检查通过。独立实验室已在 Godot 4.7.2 / Forward+ / Apple M5 实际运行，输出调试截图与[验证报告](../../godot-client/demos/painterly_lab/qa/validation.json)。包括数值深度、几何射线对照、宽笔触内外变化、镜头／光向稳定性、选择性色彩与色域测试。实验室 flow、重要度和保护图是合成测试数据，未制作蓝鸟美术图；未集成原生 GI、透明／金属 PBR 或验收完整场景性能。上表仍包含后续完整艺术验收项目，不能将它们全部视为已通过。
